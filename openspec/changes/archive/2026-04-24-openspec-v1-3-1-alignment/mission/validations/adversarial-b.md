### Commit 1: `08627c7` -- Fix darkfactory-init parallel Bash cancellation and add --force to openspec init

**Files:** `.claude/skills/darkfactory-init/SKILL.md` (+5 -1)

**What it does:**
- Adds an implementation note after Step 2 (file checks): use `test -f <path> && echo "found" || echo "missing"` pattern.
- Adds an implementation note after Step 4 (CLI checks): use `command --version 2>/dev/null || echo "NOT_INSTALLED"` pattern.
- Changes `openspec init --tools claude,codex` to `openspec init --tools claude,codex --force` on line 81.

**Findings:**

1. **MINOR -- Step 4 code block contradicts implementation note.** Lines 91-96 contain a fenced code block showing bare commands like `codex --version 2>/dev/null`. These will exit non-zero when the tool is missing. The implementation note on line 98 tells the agent to add `|| echo "NOT_INSTALLED"` -- but the code block above it does not follow this pattern. An agent that copies the code block verbatim will hit the exact bug the note is supposed to prevent. The note should have updated the code block too, or the code block should have been removed. This is not a contract violation (the contract only checks for the presence of the note), but it is a real behavioral risk.

2. **OK -- Line 83 mentions `openspec init` without `--force`.** The text is `Note: After first-time openspec init, the user needs to restart Claude Code...`. This is prose about the command generically, not an invocation instruction. The contract assertion "does NOT contain `openspec init --tools claude,codex` without the --force flag" still passes because this line says `openspec init` without the `--tools` flags. Not a problem, but worth noting for completeness.

3. **OK -- No codex copy of darkfactory-init.** The `.codex/skills/` directory has no `darkfactory-init` folder. This is correct -- darkfactory-init is a Claude Code-only skill since Codex does not run skills interactively.

**Verdict:** PASS with one minor concern (finding 1).
