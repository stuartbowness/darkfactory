## Context

Darkfactory's skills and configuration were built against OpenSpec v1.2.0. The CLI has been upgraded to v1.3.1 on this machine. Two bugs in darkfactory-init now block new project initialization, and the openspec-generated skill files carry stale metadata and content.

The codebase is entirely markdown skills, bash scripts, and config files. There is no application code, build system, or test suite. All changes are to skill definitions and documentation.

### Current state of affected files

- `darkfactory-init/SKILL.md`: Natural-language skill that tells the agent to check file existence and CLI versions. Does not prescribe exact bash commands. Two bugs: (1) file checks can exit non-zero and cancel sibling parallel Bash calls, (2) `openspec init` lacks `--force` flag.
- `openspec-{propose,apply-change,archive-change,explore}/SKILL.md` (x4 in `.claude/skills/`, x4 in `.codex/skills/`): Auto-generated by OpenSpec v1.2.0. Two of four have minor text customizations that do not change behavior.
- `README.md` line 197: `/opsx:archive` row says "Installed by `openspec init`" but the command is actually defined in `.claude/commands/opsx/archive.md`.

## Goals / Non-Goals

**Goals:**
- Fix both darkfactory-init bugs so `/darkfactory-init` works reliably
- Regenerate openspec-* skills from v1.3.1 so metadata and content match the installed CLI
- Keep `.codex/skills/` copies in sync with `.claude/skills/`
- Fix the README inaccuracy

**Non-Goals:**
- Adopt new OpenSpec v1.3.1 features (profiles, new workflows, archive CLI flags)
- Restructure `.codex/skills/` to use symlinks instead of copies (flagged as follow-up)
- Modify any CLI commands Darkfactory uses (all are stable in v1.3.1)
- Update `openspec/config.yaml` (profile system is user-level, not project-level)

## Decisions

### 1. Regenerate skills via `openspec update --force` rather than manual edits

**Why:** Regeneration picks up content improvements and ensures metadata accuracy. Manual edits would only bump the version tag and leave stale instruction text.

**Alternative considered:** Manually change `generatedBy: "1.2.0"` to `"1.3.1"` in 8 files. Rejected because it misses content changes and leaves potential drift.

**How:** Run `openspec update --force` from `~/.darkfactory` (where `openspec/config.yaml` lives). This overwrites `.claude/skills/openspec-*/SKILL.md`. Then copy those files to `.codex/skills/openspec-*/SKILL.md`.

### 2. Brief implementation note for parallel Bash cancellation, not command rewrites

**Why:** The darkfactory-init skill is natural-language. Over-prescribing exact bash commands would make the skill brittle. A one-line note steers the agent toward safe patterns while preserving flexibility.

**Alternative considered:** Rewrite steps 1-4 with exact bash commands. Rejected because it removes the agent's ability to adapt to different environments and makes the skill harder to maintain.

**What the note says:** "Use `test -f <path> && echo "found" || echo "missing"` for file checks and `command --version 2>/dev/null || echo "NOT_INSTALLED"` for CLI checks. These patterns always exit 0, preventing cancellation of sibling parallel Bash calls in Claude Code."

### 3. Add `--force` to openspec init inline

**Why:** Single-word addition to an existing command. No architectural decision needed.

### 4. README: "Bundled with Darkfactory" phrasing

**Why:** Matches the style of other rows in the skill table (short source descriptions, not file paths). Accurate: the `/opsx:archive` command is defined in `.claude/commands/opsx/archive.md`, which ships with Darkfactory.

## Risks / Trade-offs

**[Risk] Regeneration overwrites minor customizations in 2 of 4 skills** → Accepted. The customizations (compressed text, compact tables) do not change behavior. Regenerated content from v1.3.1 is more detailed, which is an improvement.

**[Risk] `openspec update --force` may change file structure or add unexpected files** → Mitigated by reviewing the diff before committing. If unexpected changes appear, we revert and investigate.

**[Risk] Future OpenSpec upgrades may require the same regeneration** → Accepted. This is the expected maintenance pattern for auto-generated skills. Could be automated in a future hook.
